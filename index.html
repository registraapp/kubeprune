What the audit looks at

The same twelve places come up again and again. None of them needs a re-architecture. The guide to the twelve cuts shows how to check each one yourself.

  • Instances, databases and nodes sized for a peak that never comes
  • Staging and dev environments running nights and weekends
  • Unattached EBS volumes and forgotten snapshots
  • NAT gateway traffic that should go through free gateway endpoints
  • gp2 volumes that could be gp3
  • Savings Plans coverage, and commitments that no longer fit
  • Workloads that could run on Spot
  • x86 instances that could move to Graviton
  • S3 buckets with no lifecycle rules
  • CloudWatch log groups kept forever
  • Public IPv4 addresses nobody uses
  • EKS clusters paying for extended support

How the audit runs

  1. Day 1: you create a read-only role. You get the exact IAM policy in advance: describe, list and billing read. No write access, no access to application data.
  2. Days 2 to 8: analysis. Three months of Cost and Usage data, actual resource utilization, EKS clusters, databases, storage and network paths.
  3. Day 9: pull requests. The quick wins land as Terraform PRs in your repository, one change per PR, each with its expected effect in the description.
  4. Day 10: report and walkthrough. The written report, ranked by priority, and a call to go through it. Then you revoke the role.

Frequently asked questions

How much does the AWS cost audit cost?

$2,400, fixed, in USD and excluding taxes. The price is the same whatever the size of the bill. The 20-minute bill review before it is free.

What access do you need to our AWS account?

A read-only IAM role that you create and can revoke at any time. You get the exact policy before you create it. It can list and describe resources and read billing data; it cannot change anything.

What do the Terraform pull requests cover?

The quick wins that are low risk and easy to review: for example gp2 to gp3 volumes, CloudWatch Logs retention, S3 lifecycle rules, and gateway endpoints for S3 and DynamoDB. You review and merge them; nothing is applied for you.

Does the audit cover Kubernetes and EKS?

Yes: node utilization, pod requests compared with real usage, Karpenter or autoscaler settings, and clusters that are paying for EKS extended support.

We don't use Terraform. Is the audit still useful?

Yes. The report is the same. The quick wins then come as a written change list with the exact AWS CLI commands instead of pull requests.

Can you work with a team in the US, the UK or Australia from France?

Yes. The audit is mostly asynchronous: read-only access, a written report, pull requests. The kickoff and the walkthrough calls are scheduled in overlapping hours.
